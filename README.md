# Customer Churn Prediction

Predicts which telecom customers are at risk of churning, using account, service, and
billing data — so retention teams can prioritize outreach before a customer leaves.

## Dataset

IBM Telco Customer Churn — 7,043 customers, 21 raw columns, binary target (`Churn`).
~26.5% churn rate (moderate class imbalance, ~2.8:1).

## Approach

1. **EDA** — scanned all categorical columns by churn-rate spread and all numeric columns
   by group-mean gap to prioritize which features to visualize, then confirmed with a
   correlation heatmap and a full grid of churn-rate-by-category bar charts
2. **Cleaning** — fixed `TotalCharges`' string dtype, imputed missing values with the
   median (distribution was right-skewed)
3. **Feature engineering** —
   - `tenure_group`: tenure binned into `0-12mo / 13-24mo / 25-48mo / 49-72mo`
     (`include_lowest=True` so zero-tenure customers are captured correctly)
   - `charge_per_month`: `TotalCharges / (tenure + 1)`, replacing `TotalCharges` itself
     once its correlation with `tenure` (~0.83) was confirmed redundant
4. **Pipeline** — `ColumnTransformer` (StandardScaler + OneHotEncoder) combined with the
   model in a single sklearn `Pipeline`, fit only on training data to prevent leakage
5. **Cross-validation** — 5-fold `StratifiedKFold`, ROC-AUC scoring
6. **Hyperparameter tuning** — `RandomizedSearchCV` (30 iterations) for XGBoost
7. **Evaluation** — ROC curve, Precision-Recall curve, confusion matrix, SHAP values
   (final model), full metric comparison table
8. **Deployment** — final pipeline serialized with `joblib`, served via a Streamlit app

## Key results

| Model | Accuracy | Recall (churn) | Precision (churn) | F1 (churn) | ROC-AUC |
|---|---|---|---|---|---|
| Logistic Regression (balanced) | 0.738 | 0.783 | 0.504 | 0.614 | 0.842 |
| **XGBoost (tuned)** | 0.715 | **0.848** | 0.479 | 0.612 | 0.846 |

**5-fold CV ROC-AUC** (confirms the test-set numbers aren't a lucky/unlucky split):
- Logistic (balanced): 0.846 ± 0.012
- XGBoost (tuned): 0.849 ± 0.011

**Final model: XGBoost (tuned).** ROC-AUC was statistically tied with Logistic Regression
across cross-validation — the gap (0.003) is smaller than either model's own fold-to-fold
variance. The deciding factor was recall on the churn class: XGBoost caught 6.5 percentage
points more actual churners (0.848 vs 0.783), which matters because the business cost of
missing a churner is higher than the cost of a false-positive retention outreach.

## Top churn drivers (via SHAP + EDA)

- Month-to-month contracts
- Low tenure — churn risk is highest in the first 12 months
- Fiber optic internet without OnlineSecurity / TechSupport add-ons
- Higher monthly charges / charge-per-month

## How to run

**1. Run the notebook** to produce `models/churn_pipeline.pkl`:
```bash
jupyter notebook customerchurn.ipynb
```
Run all cells through the export cell (saves the tuned XGBoost pipeline).

**2. Install dependencies:**
```bash
pip install -r requirements.txt
```

**3. Launch the app:**
```bash
streamlit run app.py
```

## Limitations

- Single-region, single-snapshot dataset — may not generalize to other markets or time periods
- No temporal / out-of-time validation — assumes customer behavior is stable over time
- Precision on the churn class is moderate (0.479) — roughly half of flagged customers are
  false positives, worth factoring into the cost of any retention action taken on this signal
